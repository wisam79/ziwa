# خلاصة تجربة Grido المترجمة إلى ثوابت Ziwa

> لم يبدأ **Ziwa** من فراغ ذهني؛ بل هو تقطير لأهم النجاحات والآلام الهندسية في **Grido Studio** لتفادي إعادة اختراع الأخطاء أو الوقوع في نفس القيود.

---

## 1. ما الذي عانينا منه في Grido وتلغيه بنية Ziwa من اليوم الأول؟

| الألم / التحدي في Grido | كيف يختفي معمارياً في Ziwa |
|---|---|
| **انقسام المعاينة عن التصدير** (Konva DOM Canvas في المتصفح مقابل التصدير المسطح + حيل `image-properties`/`slot-properties` للـ DPI والـ `capture`) | **محرك واحد (`Ziwa.Rendering` فوق SkiaSharp):** شاشة المعاينة والتصدير 300+ DPI والطباعة تستخدم **نفس دوال الرسم حرفياً** على `SKCanvas`. |
| **حدود ذاكرة المتصفح ونقل Base64/Blob** بين Go وReact عبر HTTP أو Wails IPC | **Zero-Copy في نفس العملية (`.NET`):** شاشة الرسم ومكتبات التصدير والماسح والطباعة تقرأ من نفس الأصول والمخازن في الذاكرة (`Stream`/`SKData`) دون تقطيع Base64. |
| **فوارق WebKitGTK vs WebView2 vs Chromium** والحاجة لبيئات E2E متعددة المتصفحات لإثبات صحة العرض | **رسم حتمي (Deterministic):** SkiaSharp + HarfBuzzSharp يرسم النصوص العربية والظلال والأقنعة بنفس البكسلات على Windows وmacOS وLinux. |
| **التقاط الأشكال وKonva `Cache` vs VRAM leaks** عند السحب/الفلاتر وإعادة رسم العقد | **كاش موحّد للأصول + عرض بالبلاطات (Tiling) عند الحاجة:** `AssetStore` يحتفظ بـ Decode مصغّر للمعاينة (`DisplayResolution`) والأصل الكامل للتصدير عند الطلب فقط مع التخلص الحتمي `Dispose()`. |
| **تضخم ملفات التوثيق (`360KB Changelog`) وكثرة المهارات الثقيلة (`20+` مهارة)** | **وثائق رشيقة من اليوم الأول:** `5` قواعد و`5` مهارات مركّزة فقط، مع `changelog/fragments/` صغير الحجم + فحص آلي سريع `scripts/docs-gate.mjs`. |

## 2. مكتسبات Grido الممتازة التي نُرحّلها كما هي إلى Ziwa

### أ. ثوابت الهندسة والطباعة (لا تقبل المساس)
1. **وحدة المليمتر هي الأصل (`MmPerInch = 25.4`):** كل أبعاد الورقة والـ Grid والنزيف (`Bleed`) وخطوط القص تُخزّن وتُحسب بالمليمتر، والتحويل للبكسل يتم فقط عند الإسقاط (`DisplayDpi` أو `ExportDpi`).
2. **ضبط الكادر غير الهدّام (`CropZoom`, `CropPanX`, `CropPanY` + `OriginalAssetId`):** قص الصورة أو تكبيرها داخل الإطار لا يتلف الأصل أبداً، ويسمح بـ «استعادة الأصل» وبخطوة `Undo` واحدة.
3. **ترتيب خط أنابيب القناع والمرشحات الثابت:**
   1. تطبيق مرشحات البكسل على الصورة المصدر.
   2. قص الشكل الهندسي (`None`, `Circle`, `Arch`, `Hexagon`, `Diamond`, `Heart`, `Star`, `Seal`) عبر `SKPath` نقي واحد مشترك مع منتقي الواجهة.
   3. رسم الخلفية الداخلية ثم الحدود (`Stroke`) ثم الظل الخارجي الواحد (دون مضاعفة الظلال).
4. **إفلات الصورة داخل الشكل + تقنيع التحديد:** إسقاط صورة فوق شكل هندسي يحوّله لحاوية صورة تحفظ أصلها وتدعم تلوين الشعارات المتجهة (`SVG` مع تعقيم محتوى SVG قبل الرسم).
5. **ثوابت الإغلاق الطباعي من Grido (`D-6`):**
   - الطباعة المباشرة لنظام ويندوز عبر GDI Spooler (JPEG افتراضي مع دعم PNG عند شفافية/حواف حادة) لا طباعة متصفح.
   - تحويل **CMYK** الحقيقي عبر **TIFF** (`Magick.NET` مع دعم ICC Profiles من البداية في Ziwa).
   - تفعيل **PDF متجه حقيقي** للنصوص والأشكال وطبقة **`CutContour`** للبلوتر (كان مؤجلاً في Grido والآن متاح أصالةً عبر `SKDocument.CreatePdf`).

### ب. ثوابت الأمان والحفظ الموثوق
1. **الكتابة الذرية (`Atomic File Write`):** أي حفظ لمشروع أو إعدادات أو ملف مصدّر يكتب أولاً في `*.tmp` مع `FileStream.Flush(flushToDisk: true)` ثم `File.Move(tmp, target, overwrite: true)` مع تنظيف `.tmp` في `finally`.
2. **صفر أسرار مشتركة في الثنائي:** كل طلب سحابي للذكاء الاصطناعي يرسل `Authorization: Bearer <UserJWT>` فقط.
3. **التحقق من حمولات الحافظة والمشاريع:** أي JSON/حافظة مقروءة تخضع لفحص مخطط صارم وأبعاد موجبة منتهية خالية من `NaN`/`Infinity`.
4. **ملكية المحاولات غير المتزامنة (`Generation / CancellationToken`):** كل عملية AI أو تصدير طويلة (`180s`) تحمل `OperationId` و`CancellationToken`؛ الإلغاء أو تبديل المشروع يمنع أي نتيجة متأخرة من تلويث المستند الحالي.
5. **جلسة واحدة نشطة (`Single Active Session Last-Wins`):** في Supabase مع أقفال `SECURITY DEFINER` وسياسات RLS صارمة (`IS NOT TRUE`).

### ج. ثوابت نظافة الكود وتجربة المستخدم
1. **توحيد الأوامر والأحداث:** لا أسماء أحداث نصية متناثرة (`grido:*`) ولا نسخ مكررة لـ `clamp` أو `AbortError` أو أزرار الاختصارات؛ كل ذلك يولد بمصدر واحد من اليوم الأول.
2. **تجربة البداية العملية والسياقية:** لا شاشة فارغة جامدة؛ قوالب بداية سريعة (صور هوية، كرت وجه/ظهر، شيت ملصقات، ورقة حرة)، وشريط سريع سياقي يبرز الفعل المناسب لنوع العنصر المحدد فقط.
3. **انتظار صادق (`Wait UX`):** `< 1s` بلا مؤشر، `1–3s` حلقة انتظار هادئة، `> 3s` أو غير محدد مع زر إلغاء صريح وشريط تقدم حقيقي عند قياس النسبة فقط.
